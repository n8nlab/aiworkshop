My starter prompts

Five prompts. A page of your own.

Copy each prompt and paste it into your AI agent, such as Claude Code, Copilot or Cursor. Work through them in order, as each step builds on the previous one. Replace the highlighted fields with your details to make the page your own.

01Role — who the agent is 02Context — where we start 03Task — what we want 04Requirements — what the result needs 05Constraints — what to avoid 06Goal — why it matters
Prompt 01

Get to know the project

Ask the agent to read and explain the project before making any changes.

# ROLE
You are an experienced web developer and mentor working with a beginner. Explain things simply in English.

# CONTEXT
We are in the AI Workshop Belgrade repository. This is a plain HTML and CSS website with no framework or build step. It is published on GitHub Pages at https://n8nlab.github.io/aiworkshop/.
- Shared styles: assets/style.css. Leave this file alone.
- My page: ljudi/marija-dimitrijevic/index.html
- My folder: ljudi/marija-dimitrijevic/. I can create pages and add images here.

# TASK
1. Read README.md, assets/style.css and ljudi/marija-dimitrijevic/index.html.
2. Explain how the site is organized in 5–7 sentences.
3. List the reusable CSS classes for cards, buttons, grids and other components.
4. Suggest three distinct visual directions for my page.

# CONSTRAINTS
- Read and explain. Leave every file as it is for this step.

# GOAL
Understand the site before I start building and choose a visual direction.
💡 Why this helps: Reading the project first helps the agent understand the structure and avoid mistakes.
Prompt 02

Make it your own

Make the page yours through your name, story, colors and style. Fill in the highlighted fields before using the prompt.

# ROLE
You are a web designer who creates personal pages with a distinctive visual style.

# CONTEXT
I am working on ljudi/marija-dimitrijevic/index.html. It currently shows my name, placeholder sections and the starter design.
- Full name: Marija Dimitrijevic
- What I do: [E.G. I WORK IN MARKETING / RUN A BUSINESS / FREELANCE]
- Three words that describe me: [E.G. PRECISE, CREATIVE, QUICK]

# TASK
Redesign my page so it reflects me and my work.

# REQUIREMENTS
1. Add my real name, initials in the avatar and a short bio of two or three sentences using the information above.
2. Visual style: [CHOOSE MINIMALIST, 80S RETRO, BLACK AND GOLD, PLAYFUL, BRUTALIST OR DESCRIBE YOUR OWN]
3. Change the accent color (--c) and put your styles in the <style> block at the top of the file.
4. Make the page look good on phones.
5. Remove the yellow starter banner.
6. Keep the starter prompts section at the bottom.

# CONSTRAINTS
- Edit only ljudi/marija-dimitrijevic/index.html.
- Leave assets/style.css and other participants’ pages alone.
- Ask me if you need personal details.

# GOAL
Help visitors understand who I am and what I do within five seconds.

# AT THE END
Give me a brief list of the changes.
💡 Why this helps: Specific details make the page more personal.
Prompt 03

A tool for my work

Add an interactive tool that solves a problem from your work, such as a calculator, quiz or quote generator.

# ROLE
You are a frontend developer who builds small, useful tools in plain JavaScript.

# CONTEXT
My page is ljudi/marija-dimitrijevic/index.html.
- What I do: [E.G. I WORK IN MARKETING / RUN A BUSINESS / FREELANCE]
- A problem I face at work: [E.G. I MANUALLY CREATE THE SAME REPORT EVERY DAY]

# TASK
Add an interactive tool that addresses this problem. It could be a price calculator, a quiz, a quote generator or a form that drafts an email or WhatsApp message.

# REQUIREMENTS
1. Suggest three ideas before writing code and wait for me to choose one.
2. Put the JavaScript and CSS in the same file using <script> and <style>, with no external libraries.
3. Make the tool work without a server or API keys.
4. Match the rest of my page.
5. Explain how the tool works in three sentences so I can show it to others.

# CONSTRAINTS
- Edit only ljudi/marija-dimitrijevic/index.html.
- Keep passwords, keys and personal data out of the code.

# GOAL
Give my page something useful for me or my clients.
💡 Why this helps: You get to choose the idea before the agent builds it.
Prompt 04

Build a small site

Add pages and subfolders to your site. Follow the path requirements to keep the links working.

# ROLE
You are a web developer who builds well-organized sites with multiple pages.

# CONTEXT
My folder is ljudi/marija-dimitrijevic/ and my main page is ljudi/marija-dimitrijevic/index.html.
The site is hosted under https://n8nlab.github.io/aiworkshop/, so relative paths matter:
- From my folder to shared CSS: ../../assets/style.css
- From a subfolder to shared CSS: ../../../assets/style.css

# TASK
Build a small site within my folder with these pages:
- ljudi/marija-dimitrijevic/[E.G. SERVICES].html — [WHAT BELONGS ON THIS PAGE]
- ljudi/marija-dimitrijevic/[E.G. PROJECTS]/index.html — [MY PROJECT LIST]
- ljudi/marija-dimitrijevic/[E.G. PROJECTS]/[E.G. PROJECT-1].html — [DETAILS OF ONE PROJECT]

# REQUIREMENTS
1. Use the same menu on each page, with links to my pages and a link to all participants at ljudi/index.html.
2. Use relative paths only. Paths must never begin with a slash.
3. Put the shared styles for my pages in ljudi/marija-dimitrijevic/stil.css and link it on each page.
4. Add visible links to the new pages on my main page.
5. Check every link and list each page, link, destination and result in a table.

# CONSTRAINTS
- Create and edit files only inside ljudi/marija-dimitrijevic/.
- Use lowercase file and folder names with hyphens and no diacritics.

# GOAL
Learn how to organize a site with several pages and folders.
💡 Why this helps: Explicit relative paths and a final link check help keep a multi-page site working.
Prompt 05

Review and publish on GitHub

Ask the agent to review your work, check the scope of your changes, make a commit and push your branch.

# ROLE
You are a careful code reviewer helping me publish my changes.

# CONTEXT
I have finished editing ljudi/marija-dimitrijevic/.
My branch is marija-dimitrijevic/moja-stranica. If it does not exist, create it from main.

# TASK
1. Check every file in my folder for broken links, unclosed tags, missing images and problems on phones.
2. Run git status. If there are changes outside my folder, stop and ask me how to proceed.
3. Show me the issues and fix them only after I approve.
4. Commit the changes with a clear message in Serbian.
5. Push marija-dimitrijevic/moja-stranica and give me a link to open a pull request.

# CONSTRAINTS
- Never push directly to main.
- Leave files outside my folder alone.

# GOAL
Get my reviewed changes onto GitHub so others can see them.
💡 Why this helps: A review gives you a chance to approve fixes before publishing.
