Glossary

Pojmovnik bez žargona

Kratka objašnjenja tehničkih termina, na srpskom, sa analogijama i upozorenjima na tipične kvarove. Klikni na pojam.

Nema pojma koji odgovara pretrazi. Dodaj ga u Q&A Log! 🙂

LLM

LLM je veliki jezički model koji predviđa sledeće delove teksta na osnovu obrazaca iz podataka. Zamisli veoma brzog saradnika koji je pročitao ogromnu biblioteku, ali može da samouvereno pogreši ako mu ne daš dobar kontekst i proveru.

Agent

Agent je model koji dobija cilj, bira sledeći korak i koristi alate da bi ga izvršio. Kao zaposleni koji dobije zadatak, pogleda u sistem, pozove drugi tim i javi rezultat, agent mora da ima granice i odobrenja.

MCP, Model Context Protocol

MCP je standardizovan način da model otkrije i koristi spoljne alate i izvore podataka. Najlakša analogija je univerzalni USB port, ali kvarovi se često kriju u dozvolama, pogrešnoj šemi ili nedostupnom serveru.

API

API je dogovoreni interfejs preko kog jedan program traži podatke ili akciju od drugog programa. Kao šalter sa obrascem, zahtev mora imati prava polja, dozvolu i format koji druga strana razume.

Webhook

Webhook je URL koji čeka događaj i pokreće workflow kada druga aplikacija pošalje podatke. To je kao zvono na vratima, ali ako su URL, metoda, autentikacija ili payload pogrešni, zvono neće zazvoniti ili će workflow dobiti neupotrebljive podatke.

JSON

JSON je tekstualni format za strukturisane podatke, sa ključevima, vrednostima, nizovima i objektima. Zamisli obrazac sa jasno imenovanim poljima, jedan višak zarez ili pogrešan tip može da sruši sledeći korak.

Workflow automation vs AI automation vs AI agent

Workflow automation prati unapred definisane korake, AI automation dodaje model tamo gde treba klasifikacija ili generisanje, a AI agent može da bira korake i poziva alate. Što je sistem fleksibilniji, to više moraš da uvedeš validaciju, logove i ograničenja.

Context window

Context window je količina teksta i podataka koju model može da razmatra u jednom pozivu. Kao radni sto, kada ga zatrpaš dokumentima, važne stvari mogu da ispadnu ili da model počne da meša delove konteksta.

Token

Token je mali deo teksta koji model obrađuje, nekad cela reč, nekad deo reči ili znak. Tokeni utiču na cenu, brzinu i limit konteksta, pa dugačak prompt i veliki output mogu da prekinu poziv.

Tool calling

Tool calling je kada model vrati strukturisan zahtev da se pozove određeni alat sa argumentima. Kao asistent koji popuni nalog za drugi tim, taj nalog mora da se proveri pre izvršenja, naročito ako menja ili briše podatke.

RAG

RAG znači da sistem prvo pronađe relevantne delove dokumenata, pa ih da modelu kao kontekst za odgovor. To je kao bibliotekar koji donese prave stranice, ali loša pretraga ili zastareli dokument vode do lošeg odgovora.

Structured output

Structured output znači da model vraća dogovorenu strukturu, na primer JSON sa obaveznim poljima, umesto slobodnog teksta. To je obrazac koji mašina može da pročita, a validacija odmah otkriva kada neko polje nedostaje ili ima pogrešan tip.

System prompt

System prompt postavlja ulogu, pravila i granice modela pre korisničkog zahteva. Kao uputstvo zaposlenom pre smene, ne rešava svaki problem i ne treba mu slepo verovati, zato kritične odluke moraju imati dodatnu proveru.

Deployment

Deployment je objavljivanje aplikacije ili workflow-a na mesto gde može da ga koristi drugi sistem ili korisnik. Kao preseljenje iz radionice u prodavnicu, proveri environment promenljive, dozvole, logove, rollback i razliku između test i produkcionog okruženja.

OAuth

OAuth omogućava da aplikaciji daš ograničen pristup drugoj usluzi bez deljenja glavne lozinke. Kao privremena propusnica, može da istekne, bude opozvana ili da ima preširoke dozvole.

Webhook debugging

Webhook debugging je sistematska provera da li je zahtev poslat, primljen, autentifikovan, parsiran i prosleđen pravom node-u. Kreni od status koda i request loga, zatim proveri metodu, headers, raw body, JSON format i timeout, ne nagađaj naslepo.
